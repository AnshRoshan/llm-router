The cache decides the cost.
So the router routes for the cache.

Most routers ask which model is smartest. llmrouter asks three questions: which model, which backend, and which cache TTL. Prompt caches are model-scoped and non-transferable, so a router that switches models mid-conversation can cost more than not routing at all. This one keeps the cache warm.

Three questions, not one

The cost of a request is not decided by the model alone. Workload class and deployment class compose instead of being decided sequentially, and scoring is per (model, backend) pair.

Quick start

Both packages ship the same decision engine. The Python package adds the async execution layer: retries, failover, adapters, and the learning loop.

Python pip install llmrouter[http] 
import asyncio
from llmrouter import Message, Router

router = Router.with_defaults(
    anthropic_key="sk-...", openai_key="sk-...",
    sidekick_model="gpt-mini-class",
)

async def main():
    out = await router.acomplete(
        [Message("system", "You are a support bot."),
         Message("user", "hi")],
        session_id="user-42",   # keeps the prompt cache warm
        workload="chat",
    )
    print(out.text)
    print(router.explain())     # every decision is auditable

asyncio.run(main())
Node.js npm install llmrouter 
import {
  Message, RoutingRequest, WorkloadClass,
  PolicyEngine, PriceRegistry, BackendRegistry,
} from "llmrouter";

const engine = new PolicyEngine(
  new PriceRegistry(), new BackendRegistry(),
);

const decision = engine.decide(new RoutingRequest(
  [new Message("user", "refactor this function")],
  WorkloadClass.Code,
  "user-42",                 // session id: sticky caching
));

decision.modelId;            // "gpt-frontier-class"
decision.backendId;          // "openai"
decision.ttlBySegment;       // system=>1h, history=>5m
console.log(decision.explain());

No keys, no network in the decision layer. Drive your own HTTP client from decide(), or use the Python acomplete() path for retries, cross-model failover and usage-counter learning.

What makes it different

Six ideas, each enforced in code and pinned by paired tests in both runtimes.

Pairs, not models

The score is per (model, backend) pair, with the two terms most routers leave out:

score = w_q·quality − w_c·cost − w_l·latency
      − w_s·switch_cost   // cache you throw away
      + w_a·affinity      // measured hit rate

The affinity bonus is learned from the usage counters every provider returns, not assumed.

TTL per breakpoint

System prompt, tool schemas and retrieved chunks are stable, so they get the 1-hour tier. Conversation history is append-only, so paying 2× to cache it is waste: 5 minutes.

tools + system + retrieved → 1h
conversation history       → 5m

The decision uses expected_gap + generation_time, because the cache lifetime is measured from the start of the request.

Stickiness with an amortization test

A one-way migration must pay back inside the turns left:

R* = (c'·w' − c·r) / ((c − c')·r)

On Anthropic that is 4.75 turns for sonnet→haiku; onto a no-write-premium provider it is under one turn. If the migration cannot pay back, the router stays put and increments a stranded counter you can see. A session that already migrated once never migrates again.

Delegate instead of switching

Mid-session model switching destroys the cache. Delegation does not: a frontier lead and a cheaper sidekick run with two separate contexts and two separate warm caches, exchanging only a brief. Routing is by task phase, which is observable from the tool-call history, not by difficulty, which is not. Planning is lead-only.

Rule F: invalidating drift

A provider's cache key covers more than the prefix: tool schemas, image usage, thinking settings. If those drift inside a pinned session, every candidate is scored cold for that turn and the decision says so. Raising thinking.effort is priced like a model switch.

Hard constraints and honest failure

Pre-call context-window validation. Residency tags fail closed: no compliant model, no call. Budget caps pick the cheapest violator and say so. The circuit breaker recovers through a single canary probe, never by calling the provider for health's sake. Decision p50 under 10 ms, enforced in tests.

The learning layer, on the command line

Pure decision layer, no keys, no network. Identical commands in both runtimes.

explain

Route one prompt and print the full auditable decision: candidates, scores, TTL choices, and why the workload class was picked.

python -m llmrouter explain --prompt "hi" --workload chat
npx llmrouter explain --prompt "hi" --workload chat

eval

Run a JSONL case file and gate it: exit code 1 when quality drops below the floor, cases become unroutable, expected models disagree, or decision p50 passes 10 ms. The pre-merge gate for routing changes.

llmrouter eval --data cases.jsonl --ci --quality-floor 0.75 --json

calibrate

Sweep the quality floor and report the value that hits your target strong-model share. The RouteLLM calibration pattern, generalized past two models.

llmrouter calibrate --data cases.jsonl --target-strong-pct 0.5

Two packages, one decision engine

Same price cards, same formulas, same scoring. The paired test suites assert identical numbers, so both runtimes agree on every decision.

Honest expectations

Budget 30–40% cost reduction at ≤2% quality loss. Numbers like 85% come from easy benchmarks and input-only cost accounting. The savings arithmetic that actually matters: if your strong/weak price gap is under about 3×, routing cannot pay for itself. Ship the eval command and measure your own traffic.
